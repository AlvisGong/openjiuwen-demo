# 服务带出场景-端到端调用栈梳理（查金豆 → 带出建议 → "好的" → 续办推荐）

> 场景：李四（轻度客户）在 L1 查金豆 → L2 委派办结后经原生 response metadata 返回带出建议 → L1 过滤投递 `service_lead_out` 事件 → 用户回复"好的" → L1 识别带出应答、新计划委派 → L2 推荐赚豆活动（场景 2：轻度客户）
>
> 实测会话：`leadout-run-e2e-002`，验证日期 2026-10-16，两轮全部成功
>
> 部署：L1 = moa-edp（18090，profiles=demo,benefit）；L2 = moa-benefit（18109，profile=benefit）
>
> 行号口径：基座类（`ServiceLeadOutCoordinator`、`StagePlanningRail`、`IntentRouter`、`IntentHandoff` 等）取自 `0.1.1\common\agents\moa-agent\src\main\java\com\moaagent\...`（moa-edp 的 pom.xml :22-24 依赖二进制 `com.moaagent:moa-agent:0.1.0`，0.1.1 目录即该库源码树）；业务类取自 moa-edp / moa-benefit 各自源码目录

```json
// 第一轮
{ "role_name": "手机银行", "input": { "query": "查金豆" },
  "custom_data": { "inputs": { "query": "查金豆", "wap_userName": "李四" } } }
```

## 2. 两轮总览

| | 第一轮 | 第二轮 |
|---|---|---|
| 用户话术 | "查金豆" | "好的"（带出应答） |
| L1 意图 | `cap.benefit.balance`（[MOA-MATCH] matches=[cap.benefit.balance]） | `cap.benefit.activities`（识别为肯定应答） |
| L1 路由 | `path=FAST reason=demo_benefit_domain` → 域卡 `cap.benefit.domain`（AGENT/COMPOSE） | 同左（demo_decline 分支未触发） |
| L1 计划 | v1-todo-1 → await_result 中断（A2A 委派） | v2-todo-1（新计划，不恢复旧栈） |
| A2A 信封 | textLen=102，`moa.intent_handoff`（COMPOSE） | textLen=101，`moa.intent_handoff` + serviceLeadOut 承接上下文 + 上一轮 assistant 消息 |
| L2 路由 | `path=SLOW reason=handoff_compose` 9 张 SKILL 卡 | 同左 |
| L2 绑定 | `cap.benefit.balance`（query） | `cap.benefit.activities`（activities） |
| 沙箱 | stdoutLength=76 → `{balance:2000}` | stdoutLength=122 → 每日签到（demo-sign-in） |
| facts/带出 | 李四轻度客户 → 场景2 → 1 项建议 | activities 不在白名单 → facts 空 → 0 项 |
| 带出通道 | L2 `filter delivery=RESPONSE_METADATA resolvedItems=1` → `metadata_published items=1` → L1 `a2a_metadata rawPresent=true leadOutItems=1` → `filter delivery=FRONTEND resolvedItems=1 acceptedItems=1` → `frontend_published items=1` | L2 `resolvedItems=0` → L1 `rawPresent=false leadOutItems=0` → `resolvedItems=0`（无二次带出） |
| SSE | final_answer（余额 2000）+ `service_lead_out` 事件（token=ff624f18…，BUTTON） | final_answer（推荐每日签到），无带出事件 |

双端口径差异（均符合设计）：L1 走 `FAST/demo_benefit_domain`（域直派），L2 域内走 `SLOW/handoff_compose`（9 卡规划）。

### 5.4 facts 生成与四类场景

- 事实源：OperationCompletionListener SPI ⑭ 统一覆盖本地 SCRIPT、Skill A2A、快路径与计划内直接 A2A；只消费已配置权益 Skill 的 native_skill_v1 回执，不把模型文本当成功（BenefitOperationObserver :71-73）。
