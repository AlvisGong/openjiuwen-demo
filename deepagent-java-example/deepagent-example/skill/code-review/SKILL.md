# Code Review Skill

专业代码评审工具，针对 Java 和 Python 代码进行全面审查。

## 触发场景

- 用户说"评审这段代码"、"review this code"、"代码审查"
- 用户请求检查代码质量、查找代码问题
- 用户提交代码前需要审查
- 用户说"帮我看看这段代码有什么问题"

## 评审维度

### 1. 代码质量
- **命名规范**：变量、函数、类的命名是否清晰、有意义
- **代码结构**：函数长度、圈复杂度、职责单一性
- **可读性**：代码是否易于理解，注释是否恰当
- **DRY 原则**：是否存在重复代码

### 2. 潜在 Bug
- 空指针/None 引用
- 边界条件处理
- 异常处理是否完善
- 资源泄漏（文件、连接未关闭）
- 并发问题（线程安全）

### 3. 性能问题
- 不必要的循环嵌套
- 低效的算法或数据结构选择
- 内存泄漏风险
- 数据库查询优化

### 4. 安全漏洞
- SQL 注入
- XSS 跨站脚本
- 敏感信息硬编码
- 输入验证缺失
- 不安全的反序列化

### 5. 最佳实践

#### Java 特有
- 使用 Optional 避免 NPE
- Stream API 的正确使用
- 合理使用设计模式
- 避免过早优化

#### Python 特有
- 遵循 PEP 8 规范
- 使用列表推导式、生成器
- 上下文管理器 (with 语句)
- 类型提示的使用

## 输出格式

评审结果以简洁的问题列表形式输出，按严重程度分类：

```
## 代码评审结果

### 严重问题 (Critical)
- [文件:行号] 问题描述
  建议修复方案

### 警告 (Warning)
- [文件:行号] 问题描述
  建议修复方案

### 建议 (Suggestion)
- [文件:行号] 问题描述
  建议修复方案

### 优点
- 值得肯定的地方
```

## 严重程度定义

| 级别 | 定义 | 示例 |
|------|------|------|
| Critical | 必须修复，可能导致崩溃、安全漏洞或数据丢失 | SQL注入、空指针、资源泄漏 |
| Warning | 应该修复，影响代码质量或可能导致问题 | 未处理的异常、性能问题 |
| Suggestion | 可选优化，提升代码可读性和维护性 | 命名改进、代码结构优化 |

## 评审流程

1. **理解上下文**：先阅读代码，理解其功能和目的
2. **逐项检查**：按照评审维度逐一检查
3. **定位问题**：精确指出问题所在的位置（文件名和行号）
4. **给出建议**：为每个问题提供具体的修复建议
5. **肯定优点**：指出代码中值得肯定的地方

## 示例

**输入：**
```python
def get_user(id):
    conn = mysql.connect()
    cursor = conn.cursor()
    cursor.execute("SELECT * FROM users WHERE id = " + id)
    return cursor.fetchone()
```

**输出：**
```
## 代码评审结果

### 严重问题 (Critical)
- [第4行] SQL 注入漏洞
  使用参数化查询：cursor.execute("SELECT * FROM users WHERE id = %s", (id,))

- [第2-3行] 资源泄漏风险
  数据库连接和游标未关闭，使用 with 语句或 try-finally 确保资源释放

### 警告 (Warning)
- [第1行] 缺少类型提示
  添加类型提示提高可读性：def get_user(id: int) -> Optional[dict]:

### 建议 (Suggestion)
- [第1行] 函数命名可更明确
  考虑使用 get_user_by_id 更清晰地表达意图

### 优点
- 函数职责单一，只做一件事
```

## 注意事项

- 评审应客观、具体，避免模糊表述
- 优先关注严重问题，不要在细节上过度纠结
- 修复建议应可操作，而非泛泛而谈
- 保持建设性态度，既指出问题也肯定优点
- 考虑项目上下文，不要过度设计
